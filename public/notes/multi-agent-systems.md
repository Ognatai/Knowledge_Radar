## EN

> **Note:** LLM-generated summary based on the listed sources; it may be incomplete, outdated or wrong.

### TL;DR

A multi-agent system lets several autonomous agents with different roles, tools or contexts work on a task by communicating with each other, instead of one agent doing everything. In LLM-based multi-agent systems, each agent is an LLM with its own profile, and the gains come from specialising agents and from their interaction, for example in software development teams, debates or simulations of societies (Guo et al., 2024). In Anthropic's research feature, a lead agent that spawns parallel subagents beat a single agent by 90.2% on an internal evaluation, but used about 15 times as many tokens as a chat (Anthropic, 2025). Gains on popular benchmarks are often small, and failures cluster in system design, misalignment between agents and missing verification (Cemri et al., 2025).

           ┌──────▼──────┐   plans, delegates, merges results
           │ lead agent  │

          └───┬┘ └┬──┘ └┬───┘
              └───┴─────┘  condensed findings → lead agent → answer

#### 1. Agents and profiles

A single LLM agent combines decision-making, tool use and memory; multi-agent systems add diverse agent profiles, interaction between agents and collective decision-making (Guo et al., 2024). Profiles describe an agent's characteristics, capabilities, behaviours and constraints, such as product manager, engineer and tester in software development, or proponent, opponent and judge in a debate. They are pre-defined by designers, generated by a model or derived from data (Guo et al., 2024).

#### 2. Communication

Agents communicate cooperatively towards a shared goal, in a debate to refine a solution, or competitively towards conflicting goals (Guo et al., 2024). The communication structure can be layered, decentralised (peer-to-peer), centralised around one or more coordinating agents, or a shared message pool to which agents publish and subscribe, as in MetaGPT; the content is usually text (Guo et al., 2024). In AutoGen, agents are "conversable" and can be backed by LLMs, tools, humans or combinations, and developers program conversation patterns in natural language or code (Wu et al., 2023).

#### 3. The environment and feedback

Agents act in a sandbox such as a code interpreter or game rules, in a physical environment such as robots, or without an external environment, as in debates (Guo et al., 2024). They learn from feedback from the environment, from other agents and from humans, and adjust through memory, self-evolution of goals and strategies, or dynamic generation of new agents (Guo et al., 2024).

#### 4. Orchestrator and workers in practice

Anthropic's research system uses an orchestrator-worker pattern: a lead agent plans, spawns three to five subagents that search in parallel, each with its own context window, and compiles their condensed findings; a separate citation agent attributes claims to sources (Anthropic, 2025). Parallelisation cut research time by up to 90% for complex queries. On the BrowseComp benchmark, token usage alone explained 80% of the performance variance (Anthropic, 2025). How agents and transitions are arranged can itself be designed as a graph ([[graph-engineering|graph engineering]]).

#### Origin and variants

Research on autonomous agents and multi-agent systems predates LLMs; traditional multi-agent systems often learned with reinforcement learning from offline data, whereas LLM-based ones mainly learn from immediate feedback in interaction (Guo et al., 2024). LLM-based multi-agent systems are used for problem solving, such as software development, embodied agents, science experiments and debate, and for world simulation, such as societies, games, economics and policy (Guo et al., 2024). Frameworks such as AutoGen, LangGraph and CrewAI provide building blocks ([[agent-frameworks|agent frameworks]]).

### When to use it

- Tasks that split into independent, parallelisable subtasks with a lot of information to process, such as broad research (Anthropic, 2025).
- Work that benefits from distinct roles or perspectives, such as reviewer and author, or debate to improve factuality (Guo et al., 2024).
- Simulations of many interacting actors (Guo et al., 2024).
- Poor fit: tasks where all agents need the same context or depend heavily on each other, most coding tasks, low-value tasks that do not justify the token cost, and real-time coordination (Anthropic, 2025).

### Strengths and limitations

**Strengths**
- Specialised agents and separate context windows let a system cover more ground than a single agent (Guo et al., 2024; Anthropic, 2025).
- Parallel subagents reduce wall-clock time (Anthropic, 2025).
- Roles and structures make the division of labour explicit and inspectable.

**Limitations**
- Much higher cost: agents used about 4 times and multi-agent systems about 15 times as many tokens as chat interactions (Anthropic, 2025).
- Errors compound: one agent's hallucination can be accepted and propagated by others (Guo et al., 2024; [[hallucination-detection|hallucination detection]]).
- In 1,600+ annotated traces across seven frameworks, failures fell into 14 modes in three groups: system design issues, inter-agent misalignment and task verification (Cemri et al., 2025).
- Evaluation is hard: benchmarks mostly test individual agents in narrow scenarios and miss emergent behaviour (Guo et al., 2024).
- Long-running, stateful agents need durable execution, checkpoints and careful deployment (Anthropic, 2025).

### Comparison

| | Single agent | Multi-agent system |
|---|---|---|
| Context | one context window | one per agent, condensed hand-overs |
| Parallelism | sequential tool calls | parallel subagents |
| Cost | lower | about 15× chat tokens (Anthropic's system) |
| Failure modes | one agent's errors | plus coordination and verification failures |
| Good for | tightly coupled tasks, most coding | broad, parallelisable tasks |

Sources: Anthropic (2025); Cemri et al. (2025); Guo et al. (2024).

### In practice

Give each subagent an objective, an output format, guidance on tools and clear task boundaries; vague instructions led to duplicated work (Anthropic, 2025). Scale the effort to the complexity of the query, and design tools with distinct purposes and clear descriptions. Start evaluation with about 20 representative queries and an LLM judge with a rubric, and add human review to catch problems such as agents preferring SEO content farms over authoritative sources (Anthropic, 2025; [[llm-as-a-judge|LLM-as-a-judge]]). Use a failure taxonomy such as MAST to classify what goes wrong in traces (Cemri et al., 2025). Keep shared state and context hand-overs small and deliberate ([[context-engineering|context engineering]]), and see [[agentic-ai|agentic AI]] for single-agent foundations.

### Key takeaway

Multi-agent systems split work across specialised, communicating agents; they pay off for broad, parallelisable tasks, but cost many more tokens and add coordination and verification failures, so a single agent remains the default for tightly coupled work.

## DE

### TL;DR

Ein Multi-Agenten-System lässt mehrere autonome Agenten mit unterschiedlichen Rollen, Werkzeugen oder Kontexten an einer Aufgabe arbeiten, indem sie miteinander kommunizieren, statt dass ein Agent alles erledigt. In LLM-basierten Multi-Agenten-Systemen ist jeder Agent ein LLM mit eigenem Profil, und die Gewinne entstehen durch die Spezialisierung der Agenten und ihr Zusammenspiel, etwa in Softwareentwicklungsteams, Debatten oder Simulationen von Gesellschaften (Guo et al., 2024). In Anthropics Recherchefunktion übertraf ein leitender Agent, der parallele Subagenten startet, einen einzelnen Agenten in einer internen Evaluation um 90,2 %, verbrauchte aber etwa 15-mal so viele Token wie ein Chat (Anthropic, 2025). Die Gewinne auf gängigen Benchmarks sind oft gering, und Fehler häufen sich beim Systementwurf, in der mangelnden Abstimmung zwischen Agenten und bei fehlender Verifikation (Cemri et al., 2025).

### Funktionsweise

```text
                 Aufgabe
                  │
           ┌──────▼──────┐   plant, delegiert, führt Ergebnisse zusammen
           │ Lead-Agent  │
           └──┬───┬───┬──┘
  Teilaufgabe │   │   │ Teilaufgabe    je Subagent: eigene Rolle/Profil, Werkzeuge, Kontextfenster
          ┌───▼┐ ┌▼──┐ ┌▼───┐
          │ A1 │ │A2 │ │ A3 │ ─── Umgebung / Werkzeuge (Suche, Code-Interpreter, APIs)
          └───┬┘ └┬──┘ └┬───┘
              └───┴─────┘  verdichtete Ergebnisse → Lead-Agent → Antwort
Strukturen: zentral (wie oben) | dezentral (Peer-to-Peer) | geschichtet | gemeinsamer Nachrichtenpool
```

#### 1. Agenten und Profile

Ein einzelner LLM-Agent verbindet Entscheidungsfindung, Werkzeugnutzung und Gedächtnis; Multi-Agenten-Systeme ergänzen unterschiedliche Agentenprofile, Interaktion zwischen Agenten und kollektive Entscheidungen (Guo et al., 2024). Profile beschreiben Eigenschaften, Fähigkeiten, Verhalten und Einschränkungen eines Agenten, etwa Produktmanager, Entwickler und Tester in der Softwareentwicklung oder Befürworter, Gegner und Richter in einer Debatte. Sie werden von Entwicklerinnen und Entwicklern vorgegeben, von einem Modell erzeugt oder aus Daten abgeleitet (Guo et al., 2024).

#### 2. Kommunikation

Agenten kommunizieren kooperativ auf ein gemeinsames Ziel hin, in einer Debatte, um eine Lösung zu verfeinern, oder kompetitiv mit widerstreitenden Zielen (Guo et al., 2024). Die Kommunikationsstruktur kann geschichtet, dezentral (Peer-to-Peer), um einen oder mehrere koordinierende Agenten zentriert oder ein gemeinsamer Nachrichtenpool sein, in den Agenten veröffentlichen und den sie abonnieren, wie bei MetaGPT; der Inhalt ist meist Text (Guo et al., 2024). In AutoGen sind Agenten „conversable“ und können auf LLMs, Werkzeugen, Menschen oder Kombinationen beruhen, und Entwicklerinnen und Entwickler programmieren Gesprächsmuster in natürlicher Sprache oder Code (Wu et al., 2023).

#### 3. Umgebung und Feedback

Agenten handeln in einer Sandbox wie einem Code-Interpreter oder Spielregeln, in einer physischen Umgebung wie bei Robotern oder ohne äußere Umgebung, wie in Debatten (Guo et al., 2024). Sie lernen aus Feedback der Umgebung, anderer Agenten und von Menschen und passen sich über Gedächtnis, Selbstentwicklung von Zielen und Strategien oder die dynamische Erzeugung neuer Agenten an (Guo et al., 2024).

#### 4. Orchestrator und Worker in der Praxis

Anthropics Recherchesystem nutzt ein Orchestrator-Worker-Muster: Ein Lead-Agent plant, startet drei bis fünf Subagenten, die parallel suchen, jeder mit eigenem Kontextfenster, und fasst ihre verdichteten Ergebnisse zusammen; ein eigener Zitations-Agent ordnet Aussagen den Quellen zu (Anthropic, 2025). Die Parallelisierung verkürzte die Recherchezeit bei komplexen Anfragen um bis zu 90 %. Auf dem Benchmark BrowseComp erklärte allein der Tokenverbrauch 80 % der Leistungsvarianz (Anthropic, 2025). Wie Agenten und Übergänge angeordnet sind, lässt sich selbst als Graph gestalten ([[graph-engineering|Graph Engineering]]).

#### Herkunft und Varianten

Forschung zu autonomen Agenten und Multi-Agenten-Systemen gab es schon vor LLMs; klassische Multi-Agenten-Systeme lernten oft mit Reinforcement Learning aus Offline-Daten, LLM-basierte dagegen vor allem aus unmittelbarem Feedback in der Interaktion (Guo et al., 2024). LLM-basierte Multi-Agenten-Systeme dienen der Problemlösung, etwa in Softwareentwicklung, verkörperten Agenten, wissenschaftlichen Experimenten und Debatten, sowie der Simulation von Welten, etwa von Gesellschaften, Spielen, Wirtschaft und Politik (Guo et al., 2024). Frameworks wie AutoGen, LangGraph und CrewAI stellen Bausteine bereit ([[agent-frameworks|Agenten-Frameworks]]).

### Wann einsetzen

- Aufgaben, die in unabhängige, parallelisierbare Teilaufgaben mit viel zu verarbeitender Information zerfallen, etwa breite Recherchen (Anthropic, 2025).
- Arbeit, die von unterschiedlichen Rollen oder Perspektiven profitiert, etwa Gutachter und Autor oder Debatten zur Verbesserung der Faktentreue (Guo et al., 2024).
- Simulationen vieler interagierender Akteure (Guo et al., 2024).
- Schlecht geeignet: Aufgaben, bei denen alle Agenten denselben Kontext brauchen oder stark voneinander abhängen, die meisten Programmieraufgaben, Aufgaben mit geringem Wert, die die Tokenkosten nicht rechtfertigen, und Koordination in Echtzeit (Anthropic, 2025).

### Stärken und Grenzen

**Stärken**
- Spezialisierte Agenten und getrennte Kontextfenster lassen ein System mehr abdecken als ein einzelner Agent (Guo et al., 2024; Anthropic, 2025).
- Parallele Subagenten verkürzen die Laufzeit (Anthropic, 2025).
- Rollen und Strukturen machen die Arbeitsteilung explizit und nachvollziehbar.

**Grenzen**
- Deutlich höhere Kosten: Agenten verbrauchten etwa 4-mal und Multi-Agenten-Systeme etwa 15-mal so viele Token wie Chat-Interaktionen (Anthropic, 2025).
- Fehler pflanzen sich fort: Die Halluzination eines Agenten kann von anderen übernommen und weitergegeben werden (Guo et al., 2024; [[hallucination-detection|Halluzinationserkennung]]).
- In über 1.600 annotierten Abläufen aus sieben Frameworks fielen Fehler in 14 Muster aus drei Gruppen: Probleme im Systementwurf, mangelnde Abstimmung zwischen Agenten und Aufgabenverifikation (Cemri et al., 2025).
- Evaluation ist schwierig: Benchmarks testen meist einzelne Agenten in engen Szenarien und übersehen emergentes Verhalten (Guo et al., 2024).
- Lang laufende, zustandsbehaftete Agenten brauchen dauerhafte Ausführung, Checkpoints und sorgfältiges Deployment (Anthropic, 2025).

### Vergleich

| | Einzelner Agent | Multi-Agenten-System |
|---|---|---|
| Kontext | ein Kontextfenster | eines je Agent, verdichtete Übergaben |
| Parallelität | sequenzielle Werkzeugaufrufe | parallele Subagenten |
| Kosten | geringer | etwa 15× Chat-Token (Anthropics System) |
| Fehlerarten | Fehler eines Agenten | zusätzlich Koordinations- und Verifikationsfehler |
| Gut für | eng gekoppelte Aufgaben, die meisten Programmieraufgaben | breite, parallelisierbare Aufgaben |

### In der Praxis

Jeder Subagent braucht ein Ziel, ein Ausgabeformat, Hinweise zu Werkzeugen und klare Aufgabengrenzen; vage Anweisungen führten zu doppelter Arbeit (Anthropic, 2025). Der Aufwand sollte zur Komplexität der Anfrage passen, und Werkzeuge sollten klar abgegrenzte Zwecke und verständliche Beschreibungen haben. Die Evaluation beginnt mit etwa 20 repräsentativen Anfragen und einem LLM-Bewerter mit Rubrik, ergänzt um menschliche Prüfung, die Probleme wie die Bevorzugung von SEO-Content-Farmen gegenüber maßgeblichen Quellen aufdeckt (Anthropic, 2025; [[llm-as-a-judge|LLM-as-a-Judge]]). Eine Fehlertaxonomie wie MAST hilft, Fehler in Abläufen einzuordnen (Cemri et al., 2025). Gemeinsamer Zustand und Kontextübergaben sollten klein und bewusst gestaltet sein ([[context-engineering|Context Engineering]]); Grundlagen einzelner Agenten beschreibt [[agentic-ai|Agentic AI]].

### Merksatz

Multi-Agenten-Systeme verteilen Arbeit auf spezialisierte, kommunizierende Agenten; sie lohnen sich bei breiten, parallelisierbaren Aufgaben, kosten aber viel mehr Token und bringen Koordinations- und Verifikationsfehler mit sich, daher bleibt ein einzelner Agent der Normalfall für eng gekoppelte Arbeit.
