### TL;DR

RAG and fine-tuning are the two common ways to give a language model domain knowledge: RAG adds retrieved documents to the prompt at inference time, [[llm-adaptation|fine-tuning]] changes the model weights. For injecting factual knowledge, RAG outperformed unsupervised fine-tuning (Ovadia et al., 2023); fine-tuning is better suited to adapting behaviour and format, and both can be combined.

### How it works

RAG employs [[retrieval-augmented-generation|retrieval-augmented generation]] to augment input context at inference without altering model parameters, while [[llm-adaptation|fine-tuning]] modifies weights via retraining. Consequently, RAG supports efficient knowledge updates without retraining, whereas fine-tuning requires retraining for new knowledge (Ovadia et al., 2023).

```text
                 RAG                        fine-tuning
changes          prompt at inference time   model weights
knowledge lives  external index             parameters
update           re-index documents         train again
cost per query   retrieval + longer prompt  inference only
combined         RAFT: fine-tune the model to answer from retrieved docs
```

#### 1. What RAG Changes

At query time, RAG retrieves relevant passages from a pre-processed knowledge base using a neural retriever. The input query is embedded and matched against a document index (a [[vector-databases|vector index]]) via nearest-neighbor search, with scoring typically `score = cosine_similarity(query_embed, doc_embed)`. Retrieved passages form an augmented prompt appended to the user query. The LLM weights remain unmodified, so knowledge updates (e.g., adding new documents) require only index modification—no retraining. This design enables dynamic knowledge integration but introduces retrieval latency and risks incomplete or irrelevant passage retrieval. The quality hinges on the retriever's effectiveness and index comprehensiveness. Lewis et al. (2020) demonstrated RAG models using a dense Wikipedia index outperform parametric-only models on open-domain QA tasks, validating this architecture. [[rag-retrieval|Retrieval accuracy]] directly impacts final output quality.

#### 2. What Fine-Tuning Changes

Fine-tuning adjusts model weights via gradient updates on domain-specific data, using either full weight updates or parameter-efficient methods like [[lora|LoRA]]. Data preparation constructs question-answer pairs from domain documents (e.g., extracted from PDFs), split into training and validation sets to monitor overfitting. Inputs are tokenized sequences (e.g., `question + answer`), and outputs are predicted responses generated by the model. The algorithm applies backpropagation to minimize a loss function (e.g., cross-entropy) over the training set. Design choices include the validation split ratio (e.g., 80-20) and selection between full and efficient fine-tuning. Trade-offs: full fine-tuning is the most expressive but the most expensive and the most prone to overfitting and to forgetting previously learned capabilities; parameter-efficient methods train only a small number of parameters, which is cheaper but can limit how much the model adapts.

#### 3. Knowledge Injection Compared

RAG integrates external knowledge during inference by retrieving relevant documents from a vector database (e.g., using `cosine_similarity` for passage matching) and augmenting the input query with this context before generation. In contrast, unsupervised fine-tuning continues training the model on raw domain text, so that it has to store the facts in its weights. Ovadia et al. (2023) compared both for knowledge injection: RAG consistently outperformed unsupervised fine-tuning, both for knowledge the model had seen during pre-training and for entirely new knowledge, and LLMs struggled to learn new facts through unsupervised fine-tuning; exposing them to numerous variations of the same fact during training may alleviate this. RAG avoids this limitation by decoupling knowledge from weights, enabling direct knowledge updates without retraining. The trade-off for RAG is dependency on a high-quality retrieval system (latency, retrieval errors); for fine-tuning, it is the need for many variations of each fact and a new training run whenever the knowledge changes.

#### 4. Cost, Latency and Maintenance

RAG incurs a one-time indexing cost for the knowledge base (e.g., embedding documents into a vector database) and a per-query cost for retrieval (with an approximate nearest-neighbour index roughly logarithmic in the number of indexed vectors) and for the longer prompt. Fine-tuning requires high initial training cost (retraining the model on new data) but has low per-query cost (only inference). Updating knowledge in RAG is achieved by adding or deleting documents in the index (e.g., via [[vector-databases|Vector Databases]]), requiring no model retraining. In contrast, fine-tuning necessitates full retraining for any knowledge update, incurring significant maintenance overhead. In an agricultural case study, Balaguer et al. (2024) measured an accuracy increase of over 6 percentage points from fine-tuning and a further 5 percentage points from RAG on top of it, i.e. the gains were cumulative; the fine-tuned model also drew on information across geographies, raising answer similarity from 47% to 72% in one experiment.

#### 5. Combining Both (RAFT)

RAFT (Retrieval Augmented FineTuning), introduced by Zhang et al. (2024), is a training recipe for answering questions in an "open-book", in-domain setting. Each training example consists of a question, a set of retrieved documents that includes distractor documents not helpful for the answer, and a target answer. The model is trained to ignore the distractors and to cite verbatim the sequence from the relevant document that answers the question, within a chain-of-thought-style response. Design choices prioritize transparency and factual grounding: verbatim citation reduces hallucinations by anchoring answers to source text, but requires high-quality retrieval to ensure the relevant passage is present. This incurs trade-offs: increased training complexity due to distractor handling and precise passage extraction demands, versus improved answer reliability. RAFT keeps retrieval at inference time but fine-tunes the model to use retrieved documents well; Zhang et al. (2024) report consistent improvements in domain-specific RAG on PubMed, HotpotQA and Gorilla.

#### Origin and variants

RAG, formalized by Lewis et al. (2020), integrates parametric memory (a pre-trained sequence-to-sequence model) and non-parametric memory (a dense vector index of external documents) for language generation. Inputs consist of a user query and documents retrieved from the non-parametric index by a neural retriever, which scores documents by the inner product of query and document embeddings. The system outputs a generated response conditioned on both the query and retrieved passages. The non-parametric memory employs an approximate nearest-neighbor index (e.g., FAISS) for efficient document retrieval, while the parametric component handles generation. Design choices prioritize dynamic knowledge updates without retraining, enabling external knowledge sources to evolve independently. Trade-offs include reliance on retrieval quality (missed documents reduce output accuracy) and added latency from the retrieval step, contrasting with fine-tuning's static knowledge integration but avoiding the need for weight updates. This architecture supports factual grounding and source attribution, though retrieval errors remain a key limitation [[rag-retrieval|retrieval]] and differs fundamentally from [[llm-adaptation|fine-tuning]]'s weight-modification approach.

### When to use it

- RAG: factual knowledge that is new or changes often, since RAG outperformed unsupervised fine-tuning for knowledge injection (Ovadia et al., 2023).
- RAG: answers must cite their sources, or knowledge must be deleted again (e.g. personal data).
- Fine-tuning: the model should change its behaviour, style or output format, or learn a task rather than facts.
- Both: domain applications where adapting the model and retrieving current documents each add accuracy (Balaguer et al., 2024; Zhang et al., 2024).

### Strengths and limitations

**Strengths**
- RAG consistently outperforms unsupervised fine-tuning on knowledge-intensive tasks for both existing and new knowledge (Ovadia et al., 2023).
- RAG achieves state-of-the-art results on open domain question answering tasks, generating more specific, diverse, and factual language (Lewis et al., 2020).
- RAG and fine-tuning can complement each other: in an agricultural case study their accuracy gains were cumulative (Balaguer et al., 2024).

**Limitations**
- RAG requires additional infrastructure for [[rag-retrieval|retrieval]] and indexing, and every query pays for retrieval and a longer prompt.
- Unsupervised fine-tuning is unreliable for teaching new facts (Ovadia et al., 2023), and every knowledge update requires another training run.
- Models used with RAG can be misled by retrieved documents that do not help to answer the question, which RAFT trains models to ignore (Zhang et al., 2024).

### Comparison

| Approach | How it differs | Suited for |
|----------|----------------|------------|
| RAG | Incorporates external knowledge at inference via document retrieval, without modifying model weights. | Knowledge-intensive tasks requiring current, external, or frequently updated factual information. |
| Fine-tuning | Modifies model weights via training on task-specific data, embedding knowledge directly into the model parameters. | Adapting model behavior for specific tasks, domain-specific styles, or static knowledge bases. |
| RAG + fine-tuning (e.g. RAFT) | Fine-tunes the model to answer from retrieved documents and to ignore distractors. | Domain-specific question answering with a stable domain and changing documents. |

RAG excels at integrating new factual information without retraining (Ovadia et al., 2023), while fine-tuning is more efficient for static domain adaptation [[llm-adaptation|LLM Adaptation]].

### In practice

Evaluation requires separate assessment of retrieval efficacy (e.g., `Recall@k`) and generation accuracy, as detailed in [[rag-evaluation|evaluation]]. Fine-tuning often fails to incorporate new factual knowledge without multiple variations of the same fact (Ovadia et al., 2023). Lewis et al. (2020) describe two ways to use the retrieved passages: the same passages for the whole output (RAG-Sequence) or possibly different passages per generated token (RAG-Token).

### Key takeaway

RAG dynamically augments inference context with external knowledge for updatable factual information (with potential retrieval failures), while fine-tuning permanently embeds knowledge in model weights to adapt behavior for specific tasks (requiring retraining for new facts).

## DE

> **Hinweis:** LLM-generierte Zusammenfassung auf Grundlage der angegebenen Quellen; sie kann unvollständig, veraltet oder falsch sein.

### TL;DR

RAG und Fine-Tuning sind die beiden gängigen Wege, um einem Sprachmodell Fachwissen zu vermitteln: RAG fügt zur Inferenzzeit abgerufene Dokumente in den Prompt ein, [[llm-adaptation|Fine-Tuning]] verändert die Modellgewichte. Bei der Einbringung fakтиschen Wissens übertrifft RAG das unüberwachte Fine-Tuning (Ovadia et al., 2023); Fine-Tuning ist besser geeignet, um Verhalten und Format anzupassen, und beide Methoden können kombiniert werden.

### Funktionsweise

RAG nutzt [[retrieval-augmented-generation|retrieval-augmented generation], um die Eingabe kontextuell während der Inferenz zu erweitern, ohne die Modellparameter zu verändern, während [[llm-adaptation|fine-tuning] die Gewichte durch Neutraining verändert. Daher unterstützt RAG effiziente Wissensaktualisierungen ohne Neutraining, während fine-tuning für neue Wissen Neutraining erfordert (Ovadia et al., 2023).

```text
                 RAG                        fine-tuning
changes          Prompt zur Zeit der Inferenz   Modellgewichte
Wissen liegt     externer Index               Parameter
Aktualisierung   Dokumente neu indizieren     erneut trainieren
Kosten pro Abfrage Retrieval + langer Prompt  Nur Inferenz
Kombination      RAFT: Modell feinabstimmen, um aus abgerufenen Dokumenten zu antworten
```

#### 1. Was RAG verändert

Bei der Abfragezeit ruft RAG relevante Abschnitte aus einer vorverarbeiteten Wissensbasis mithilfe eines neuronalen Retrievers ab. Die Eingabeabfrage wird eingebettet und mit einem Dokumentindex (einem [[vector-databases|Vektorindex]]) über eine Nachbarschaftssuche abgeglichen, wobei die Bewertung typischerweise `score = cosine_similarity(query_embed, doc_embed)` lautet. Die abgerufenen Abschnitte bilden einen erweiterten Prompt, der an die Benutzerabfrage angehängt wird. Die Gewichte des Sprachmodells bleiben unverändert, sodass Wissensaktualisierungen (z. B. das Hinzufügen neuer Dokumente) nur eine Änderung des Index erfordern – kein Neutraining. Dieses Design ermöglicht die dynamische Integration von Wissen, führt aber zu Retrieval-Latenz und birgt das Risiko unvollständiger oder irrelevanter Passageabfragen. Die Qualität hängt von der Effektivität des Retrievers und der Umfassung des Indexes ab. Lewis et al. (2020) zeigten, dass RAG-Modelle mit einem dichten Wikipedia-Index bei offenen Domain-QA-Aufgaben parametrisch ausschließlich Modellen überlegen sind, was diese Architektur bestätigt. [[rag-retrieval|Retrievalgenauigkeit]] beeinflusst direkt die Qualität des Endoutputs.

#### 2. Was das Fine-Tuning verändert

Fine-Tuning passt die Modellgewichte durch Gradient-Updates anhand von domänenspezifischen Daten an, wobei entweder vollständige Gewichtsaktualisierungen oder parameter-effiziente Methoden wie [[lora|LoRA]] verwendet werden. Die Datenbereitung erstellt Frage-Antwort-Paare aus Dokumenten der Domäne (z. B. extrahiert aus PDFs), die in Trainings- und Validierungsdatensätze aufgeteilt werden, um Überanpassung zu überwachen. Die Eingaben sind tokenisierte Sequenzen (z. B. `Frage + Antwort`), und die Ausgaben sind von dem Modell generierte vorhergesagte Antworten. Der Algorithmus wendet das Backpropagation-Verfahren an, um eine Verlustfunktion (z. B. Kreuzentropie) über den Trainingsdatensatz zu minimieren. Gestaltungswahlmöglichkeiten umfassen den Verhältniswert der Validierungsaufteilung (z. B. 80-20) und die Auswahl zwischen vollständigem und effizientem Fine-Tuning. Kompromisse: Vollständiges Fine-Tuning ist am ausdrucksstärksten, aber auch am teuersten und am anfälligsten für Überanpassung und das Vergessen bereits gelernter Fähigkeiten; parameter-effiziente Methoden trainieren nur eine kleine Anzahl an Parametern, was günstiger ist, aber den Grad, zu dem das Modell sich anpasst, begrenzen kann.

#### 3. Vergleich der Wissensinjektion

RAG integriert während der Inferenz externes Wissen, indem es relevante Dokumente aus einer Vektordatenbank (z. B. durch die Verwendung von `cosine_similarity` zur Passageübereinstimmung) abruft und diese Kontextinformationen vor der Generierung zur Eingabeabfrage hinzufügt. Im Gegensatz dazu erfolgt das unsupervised fine-tuning durch das Weitertrainieren des Modells anhand von Rohdomaintext, sodass es die Fakten in seine Gewichte speichern muss. Ovadia et al. (2023) verglichen beide Ansätze bezüglich der Wissensinjektion: RAG übertraf konsistent das unsupervised fine-tuning, sowohl für Wissen, das das Modell während der Vorabtrainierung gesehen hatte, als auch für vollkommen neue Wissen, und LLMs hatten Schwierigkeiten, neue Fakten durch unsupervised fine-tuning zu erlernen; das Exponieren der Modelle gegenüber zahlreichen Variationen desselben Fakts während des Trainings könnte dies mildern. RAG umgeht diese Einschränkung, indem es das Wissen von den Gewichten entkoppelt und direkte Wissensupdates ohne Neutraining ermöglicht. Der Kompromiss für RAG besteht in der Abhängigkeit von einem hochwertigen Retrieval-System (Verzögerung, Retrievalfehler); bei fine-tuning ist es die Notwendigkeit vieler Variationen jedes Fakts und ein neuer Trainingsdurchlauf, sobald sich das Wissen ändert.

#### 4. Kosten, Latenz und Wartung

RAG verursacht eine einmalige Indexierungskosten für die Wissensbasis (z. B. das Einbetten von Dokumenten in eine Vektordatenbank) und Kosten pro Abfrage für die Retrieval (mit einem Approximate Nearest Neighbor-Index, der ungefähr logarithmisch in der Anzahl der indizierten Vektoren ist) sowie für den längeren Prompt. Fine-Tuning erfordert hohe anfängliche Trainingskosten (Neutraining des Modells mit neuen Daten), hat aber niedrige Kosten pro Abfrage (nur Inferenz). Das Aktualisieren von Wissen in RAG erfolgt durch Hinzufügen oder Löschen von Dokumenten im Index (z. B. über [[vector-databases|Vektordatenbanken]), wodurch kein Modell-Retraining erforderlich ist. Im Gegensatz dazu erfordert Fine-Tuning ein vollständiges Retraining bei jeder Wissensaktualisierung und verursacht erhebliche Wartungskosten. In einem landwirtschaftlichen Fallbeispiel haben Balaguer et al. (2024) eine Genauigkeitssteigerung von über 6 Prozentpunkten durch Fine-Tuning und eine weitere Steigerung von 5 Prozentpunkten durch RAG gemessen, d. h. die Gewinne waren kumulativ; das fine-tuned Modell nutzte auch Informationen über verschiedene Geografien, wodurch die Ähnlichkeit der Antworten in einem Experiment von 47 % auf 72 % anstieg.

#### 5. Beide kombinieren (RAFT)

RAFT (Retrieval Augmented FineTuning), eingeführt von Zhang et al. (2024), ist ein Trainingsrezept zur Beantwortung von Fragen in einer „offenen Buch“-Umgebung innerhalb eines bestimmten Bereichs. Jeder Trainingsbeispiel besteht aus einer Frage, einer Menge abgerufener Dokumente, die Distraktor-Dokumente enthalten, die für die Antwort nicht hilfreich sind, und einer Zielantwort. Das Modell wird trainiert, die Distraktoren zu ignorieren und innerhalb einer Antwort im Stil einer Gedankenfolge wörtlich den Abschnitt aus dem relevanten Dokument zu zitieren, der die Frage beantwortet. Die Designentscheidungen priorisieren Transparenz und faktenbasierte Grundierung: Das wörtliche Zitieren reduziert Halluzinationen, indem es Antworten an den Quelltext anbindet, erfordert aber eine hochwertige Retrieval-Technik, um sicherzustellen, dass der relevante Abschnitt vorhanden ist. Dies führt zu Kompromissen: Erhöhte Trainingskomplexität aufgrund der Verarbeitung von Distraktoren und der Anforderungen an präzise Abschnitte im Vergleich zu verbesserten Antwortverlässlichkeit. RAFT behält das Retrieval zur Inferenzzeit bei, fine-tunes aber das Modell, um die abgerufenen Dokumente gut zu nutzen; Zhang et al. (2024) berichten konsistente Verbesserungen bei domänenspezifischem RAG auf PubMed, HotpotQA und Gorilla.

#### Ursprung und Varianten

RAG, formalisiert von Lewis et al. (2020), integriert parametrisches Gedächtnis (ein vortrainiertes sequenz-zu-sequenz-Modell) und nicht-parametrisches Gedächtnis (einen dichten Vektorindex externer Dokumente) zur Sprachgenerierung. Eingaben bestehen aus einer Benutzeranfrage und Dokumenten, die aus dem nicht-parametrischen Index durch einen neuronalen Retriever abgerufen werden, der Dokumente anhand des Skalarprodukts von Anfrage- und Dokument-Embeddings bewertet. Das System erzeugt eine Antwort, die sowohl auf der Anfrage als auch auf den abgerufenen Passagen basiert. Das nicht-parametrische Gedächtnis verwendet einen Approximate Nearest Neighbor-Index (z. B. FAISS) für effiziente Dokumentabfragen, während der parametrische Teil die Generierung übernimmt. Gestaltungswahl priorisieren dynamische Wissensaktualisierungen ohne Neutraining, wodurch externe Wissensquellen unabhängig weiterentwickelt werden können. Kompromisse umfassen die Abhängigkeit von der Retrieval-Qualität (fehlende Dokumente verringern die Genauigkeit der Ausgabe) und erhöhte Latenz durch den Retrieval-Schritt, im Gegensatz zur statischen Wissensintegration durch Fine-Tuning, vermeiden jedoch das Bedürfnis nach Gewichtsaktualisierungen. Diese Architektur unterstützt faktenbasierte Verankerung und Quellenangaben, obwohl Retrieval-Fehler weiterhin eine zentrale Einschränkung darstellen [[rag-retrieval|Retrieval]] und sich grundlegend von der Gewichtsmodifikationsmethode von [[llm-adaptation|Fine-Tuning]] unterscheidet.

### Wann einsetzen

- RAG: Faktenwissen, das neu ist oder häufig verändert wird, da RAG bei der Wissensinjektion besser abschneidet als das unüberwachte Fine-Tuning (Ovadia et al., 2023).
- RAG: Antworten müssen ihre Quellen zitieren, oder das Wissen muss erneut gelöscht werden (z. B. persönliche Daten).
- Fine-Tuning: Das Modell sollte sein Verhalten, Stil oder Ausgabeformat ändern oder eine Aufgabe erlernen, anstatt Fakten zu erlernen.
- Beide: Anwendungen im Bereich, bei denen das Anpassen des Modells und das Abrufen aktueller Dokumente jeweils die Genauigkeit erhöhen (Balaguer et al., 2024; Zhang et al., 2024).

### Stärken und Grenzen

**Vorteile**
- RAG übertrifft konsistent das unüberwachte Fine-Tuning bei wissensintensiven Aufgaben sowohl für bestehendes als auch für neues Wissen (Ovadia et al., 2023).
- RAG erzielt state-of-the-art Ergebnisse bei Aufgaben des offenen Domain-Fragebeantwortens, wobei mehr spezifische, diverse und faktenbasierte Sprache generiert wird (Lewis et al., 2020).
- RAG und Fine-Tuning können sich gegenseitig ergänzen: in einer landwirtschaftlichen Fallstudie waren ihre Genauigkeitsgewinne kumulativ (Balaguer et al., 2024).

**Einschränkungen**
- RAG benötigt zusätzliche Infrastruktur für [[rag-retrieval|retrieval]] und Indexierung, und jede Abfrage zahlt für die Retrieval und einen längeren Prompt.
- Unüberwachtes Fine-Tuning ist für das Beibringen neuer Fakten unzuverlässig (Ovadia et al., 2023), und jede Wissensaktualisierung erfordert einen weiteren Trainingsdurchlauf.
- Modelle, die mit RAG verwendet werden, können durch abgerufene Dokumente täuscht werden, die nicht helfen, die Frage zu beantworten, was RAFT trainiert, um zu ignorieren (Zhang et al., 2024).

### Vergleich

| Ansatz | Unterschiede | Geeignet für |
|----------|----------------|------------|
| RAG | Integriert externe Kenntnisse während der Inferenz über die Dokumentrecherche, ohne die Modellgewichte zu ändern. | Wissensintensive Aufgaben, die aktuelle, externe oder häufig aktualisierte fakтиsche Informationen erfordern. |
| Fine-Tuning | Ändert die Modellgewichte durch das Training auf datenspezifischen Aufgaben, wodurch das Wissen direkt in die Modellparameter eingebettet wird. | Anpassen des Modellverhaltens für spezifische Aufgaben, domänenspezifische Stile oder statische Wissensdatenbanken. |
| RAG + Fine-Tuning (z. B. RAFT) | Fine-Tuning des Modells, um auf die aus den Dokumenten abgerufenen Informationen zu antworten und Störfaktoren zu ignorieren. | Domänenspezifisches Fragebeantworten mit stabiler Domäne und sich ändernden Dokumenten. |

RAG ist hervorragend darin, neue fakтиsche Informationen zu integrieren, ohne Neutraining durchzuführen (Ovadia et al., 2023), während Fine-Tuning effizienter für die Anpassung an statische Domänen ist [[llm-adaptation|LLM-Anpassung]].

### In der Praxis

Die Evaluation erfordert eine separate Beurteilung der Retrieval-Effektivität (z. B. `Recall@k`) und der Generationsgenauigkeit, wie im [[rag-evaluation|evaluation]] detailliert beschrieben. Das Fine-Tuning schlägt oft fehl, neue faktenbasierte Kenntnisse ohne mehrere Varianten desselben Fakts zu integrieren (Ovadia et al., 2023). Lewis et al. (2020) beschreiben zwei Arten, die abgerufenen Passagen zu verwenden: dieselben Passagen für die gesamte Ausgabe (RAG-Sequence) oder möglicherweise unterschiedliche Passagen pro generiertem Token (RAG-Token).

### Merksatz

RAG erweitert dynamisch den Inferenzkontext mit externem Wissen, um aktualisierbare fakтиsche Informationen (mit potenziellen Retrieval-Fehlern) zu unterstützen, während Fine-Tuning das Wissen dauerhaft in die Modellgewichte einbettet, um das Verhalten für spezifische Aufgaben anzupassen (was Neutraining für neue Fakten erfordert).
