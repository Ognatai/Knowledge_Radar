### TL;DR

RAG dynamically incorporates external knowledge during inference by retrieving relevant documents, outperforming unsupervised fine-tuning on knowledge-intensive tasks (Ovadia et al., 2023). This approach solves the problem of updating LLMs with new or current factual information without retraining, unlike [[llm-adaptation|fine-tuning]] which alters model weights and struggles to integrate new knowledge.

### How it works

RAG employs [[retrieval-augmented-generation|retrieval-augmented generation]] to augment input context at inference without altering model parameters, while [[llm-adaptation|fine-tuning]] modifies weights via retraining. Consequently, RAG supports efficient knowledge updates without retraining, whereas fine-tuning requires retraining for new knowledge (Ovadia et al., 2023).

```text
RAG: Modifies input context at inference time
▼
Fine-Tuning: Modifies model parameters via retraining
▼
Knowledge: External via retrieval (RAG), internal in weights (FT)
▼
Cost: RAG low maintenance, FT high retraining cost
▼
RAFT: Training recipe combining RAG and FT (Zhang et al., 2024)
```

#### 1. What RAG Changes

At query time, RAG retrieves relevant passages from a pre-processed knowledge base using a neural retriever. The input query is embedded and matched against a document index (a [[vector-databases|vector index]]) via nearest-neighbor search, with scoring typically `score = cosine_similarity(query_embed, doc_embed)`. Retrieved passages form an augmented prompt appended to the user query. The LLM weights remain unmodified, so knowledge updates (e.g., adding new documents) require only index modification—no retraining. This design enables dynamic knowledge integration but introduces retrieval latency and risks incomplete or irrelevant passage retrieval. The quality hinges on the retriever's effectiveness and index comprehensiveness. Lewis et al. (2020) demonstrated RAG models using a dense Wikipedia index outperform parametric-only models on open-domain QA tasks, validating this architecture. [[rag-retrieval|Retrieval accuracy]] directly impacts final output quality.

#### 2. What Fine-Tuning Changes

Fine-tuning adjusts model weights via gradient updates on domain-specific data, using either full weight updates or parameter-efficient methods like [[lora|LoRA]]. Data preparation constructs question-answer pairs from domain documents (e.g., extracted from PDFs), split into training and validation sets to monitor overfitting. Inputs are tokenized sequences (e.g., `question + answer`), and outputs are predicted responses generated by the model. The algorithm applies backpropagation to minimize a loss function (e.g., cross-entropy) over the training set. Design choices include the validation split ratio (e.g., 80-20) and selection between full and efficient fine-tuning. Trade-offs entail higher computational costs and overfitting risk with full fine-tuning versus potentially reduced performance gains and catastrophic forgetting with parameter-efficient approaches.

#### 3. Knowledge Injection Compared

RAG integrates external knowledge during inference by retrieving relevant documents from a vector database (e.g., using `cosine_similarity` for passage matching) and augmenting the input query with this context before generation. In contrast, unsupervised fine-tuning updates model weights via gradient descent on training examples (input: question-answer pairs; output: adjusted parameters), requiring the model to internalize facts parametrically. Ovadia et al. (2023) demonstrate that fine-tuning struggles to learn new factual information due to the model's parametric memory not efficiently accommodating novel facts, and that exposing models to numerous variations of the same fact during training mitigates this issue. RAG avoids this limitation by decoupling knowledge from weights, enabling direct knowledge updates without retraining. The trade-off for RAG is dependency on a high-quality retrieval system (introducing latency and potential retrieval errors), while fine-tuning's trade-off is the need for extensive training data variations to achieve even modest fact retention, making it inefficient for dynamic knowledge integration.

#### 4. Cost, Latency and Maintenance

RAG incurs a one-time indexing cost for the knowledge base (e.g., embedding documents into a vector database) and a per-query cost dominated by retrieval latency (e.g., `O(k log n)` for `k`-nearest neighbors in an `n`-dimensional index). Fine-tuning requires high initial training cost (retraining the model on new data) but has low per-query cost (only inference). Updating knowledge in RAG is achieved by adding or deleting documents in the index (e.g., via [[vector-databases|Vector Databases]]), requiring no model retraining. In contrast, fine-tuning necessitates full retraining for any knowledge update, incurring significant maintenance overhead. Balaguer et al. (2024) demonstrated this in an agricultural domain case study: RAG provided a 5 p.p. accuracy boost that was cumulative with fine-tuning's 6 p.p. improvement, but the fine-tuned model required retraining to incorporate new geographic knowledge, while RAG allowed continuous updates without retraining.

#### 5. Combining Both (RAFT)

RAFT (Retrieval Augmented FineTuning), introduced by Zhang et al. (2024), trains a model to generate answers directly from retrieved documents while explicitly citing relevant passages. Input comprises a question, a set of retrieved documents (including distractors), and a target answer with verbatim citation. The model output integrates the citation into a chain-of-thought response, suppressing distractors via a cross-entropy loss that prioritizes passage extraction over generation. The training data structure consists of (question, retrieved_docs, cited_passage) triples, where distractors are intentionally included to teach the model to filter irrelevant content. Design choices prioritize transparency and factual grounding: verbatim citation reduces hallucinations by anchoring answers to source text, but requires high-quality retrieval to ensure the relevant passage is present. This incurs trade-offs: increased training complexity due to distractor handling and precise passage extraction demands, versus improved answer reliability. RAFT extends [[retrieval-augmented-generation|retrieval-augmented generation]] by embedding retrieval context into the model’s weights, and [[llm-adaptation|fine-tuning]] by enabling domain-specific factual alignment without retraining the entire model.

#### Origin and variants

RAG, formalized by Lewis et al. (2020), integrates parametric memory (a pre-trained sequence-to-sequence model) and non-parametric memory (a dense vector index of external documents) for language generation. Inputs consist of a user query and retrieved documents (from the non-parametric index via a neural retriever), with retrieval scores computed as `score = 1 / (k + rank)`. The system outputs a generated response conditioned on both the query and retrieved passages. The non-parametric memory employs an approximate nearest-neighbor index (e.g., FAISS) for efficient document retrieval, while the parametric component handles generation. Design choices prioritize dynamic knowledge updates without retraining, enabling external knowledge sources to evolve independently. Trade-offs include reliance on retrieval quality (missed documents reduce output accuracy) and added latency from the retrieval step, contrasting with fine-tuning's static knowledge integration but avoiding the need for weight updates. This architecture supports factual grounding and source attribution, though retrieval errors remain a key limitation [[rag-retrieval|retrieval]] and differs fundamentally from [[llm-adaptation|fine-tuning]]'s weight-modification approach.

### When to use it

- For knowledge-intensive tasks requiring new or frequently updated factual information, as RAG consistently outperforms fine-tuning on such tasks (Ovadia et al., 2023).
- For applications requiring explicit source attribution for generated answers, as RAG retrieves and cites relevant documents (Lewis et al., 2020).
- For scenarios involving large, external knowledge bases that change independently of model updates, as RAG enables dynamic knowledge integration (Balaguer et al., 2024).

### Strengths and limitations

**Strengths**
- RAG consistently outperforms unsupervised fine-tuning on knowledge-intensive tasks for both existing and new knowledge (Ovadia et al., 2023).
- RAG achieves state-of-the-art results on open domain question answering tasks, generating more specific, diverse, and factual language (Lewis et al., 2020).
- RAG increases accuracy by 5 percentage points in domain-specific applications (Balaguer et al., 2024).

**Limitations**
- RAG requires additional infrastructure for [[rag-retrieval|retrieval]] and indexing (Lewis et al., 2020).
- Standard RAG may fail to ignore distractor documents, potentially leading to inaccurate outputs (Zhang et al., 2024).

### Comparison

| Approach | How it differs | Suited for |
|----------|----------------|------------|
| RAG | Incorporates external knowledge at inference via document retrieval, without modifying model weights. | Knowledge-intensive tasks requiring current, external, or frequently updated factual information. |
| Fine-tuning | Modifies model weights via training on task-specific data, embedding knowledge directly into the model parameters. | Adapting model behavior for specific tasks, domain-specific styles, or static knowledge bases. |
RAG excels at integrating new factual information without retraining (Ovadia et al., 2023), while fine-tuning is more efficient for static domain adaptation [[llm-adaptation|LLM Adaptation]].

### In practice

Evaluation requires separate assessment of retrieval efficacy (e.g., `Recall@k`) and generation accuracy, as detailed in [[rag-evaluation|evaluation]]. Fine-tuning often fails to incorporate new factual knowledge without multiple variations of the same fact (Ovadia et al., 2023). A key RAG parameter is context management: using a single retrieved context for the full response versus dynamic context per token, with the latter improving generation quality (Lewis et al., 2020).

### Key takeaway

RAG dynamically augments inference context with external knowledge for updatable factual information (with potential retrieval failures), while fine-tuning permanently embeds knowledge in model weights to adapt behavior for specific tasks (requiring retraining for new facts).

### TL;DR

RAG integriert dynamisch externe Kenntnisse während der Inferenz, indem relevante Dokumente abgerufen werden, und übertrifft dabei das feine Tuning ohne Überwachung bei wissensintensiven Aufgaben (Ovadia et al., 2023). Dieser Ansatz löst das Problem, LLMs mit neuen oder aktuellen faktenbasierten Informationen zu aktualisieren, ohne sie erneut zu trainieren, im Gegensatz zu [[llm-adaptation|fine-tuning]], das die Modellgewichte verändert und Schwierigkeiten hat, neue Kenntnisse zu integrieren.

### Funktionsweise

RAG verwendet [[retrieval-augmented-generation|retrieval-augmented generation], um die Eingabe kontextuell während der Inferenz zu erweitern, ohne die Modellparameter zu verändern, während [[llm-adaptation|fine-tuning] die Gewichte durch Neuerlernen verändert. Daher unterstützt RAG effiziente Wissensaktualisierungen ohne Neuerlernen, während fine-tuning für neues Wissen Neuerlernen erfordert (Ovadia et al., 2023).

```text
RAG: Modifiziert den Eingabe-Kontext zur Zeit der Inferenz
▼
Fine-Tuning: Modifiziert die Modellparameter durch Neuerlernen
▼
Wissen: Extern über Retrieval (RAG), intern in den Gewichten (FT)
▼
Kosten: RAG geringe Wartungskosten, FT hohe Neuerlernkosten
▼
RAFT: Trainingsrezept, das RAG und FT kombiniert (Zhang et al., 2024)
```

#### 1. Was RAG verändert

Bei der Abfragezeit ruft RAG relevante Abschnitte aus einer vorverarbeiteten Wissensbasis mithilfe eines neuronalen Retriever ab. Die Eingabeabfrage wird eingebettet und mit einem Dokumentindex (einem [[vector-databases|Vektorindex]]) über eine Nachbarsuche abgeglichen, wobei die Bewertung typischerweise `score = cosine_similarity(query_embed, doc_embed)` lautet. Die abgerufenen Abschnitte bilden einen erweiterten Prompt, der an die Benutzerabfrage angehängt wird. Die Gewichte des Sprachmodells bleiben unverändert, sodass Wissensaktualisierungen (z. B. das Hinzufügen neuer Dokumente) nur eine Änderung des Index erfordern – kein Neutraining. Dieses Design ermöglicht eine dynamische Wissensintegration, führt aber zu Retrieval-Latenz und birgt Risiken für unvollständige oder irrelevante Passage-Retrieval. Die Qualität hängt von der Effektivität des Retriever und der Umfassung des Index ab. Lewis et al. (2020) zeigten, dass RAG-Modelle, die einen dichten Wikipedia-Index verwenden, bei offenen Domänen-QA-Aufgaben parametrisch-only-Modellen überlegen sind, was diese Architektur bestätigt. [[rag-retrieval|Retrievalgenauigkeit]] beeinflusst direkt die Qualität des Endoutputs.

#### 2. Was verändert das Fine-Tuning

Fine-Tuning passt die Modellgewichte durch Gradient-Updates an, die auf domain-spezifischen Daten basieren, wobei entweder vollständige Gewichtsaktualisierungen oder parameter-effiziente Methoden wie [[lora|LoRA]] verwendet werden. Die Datenvorbereitung erstellt Frage-Antwort-Paare aus Domain-Dokumenten (z. B. extrahiert aus PDFs), die in Trainings- und Validierungsdatensätze aufgeteilt werden, um Überanpassung zu überwachen. Die Eingaben sind tokenisierte Sequenzen (z. B. `Frage + Antwort`), und die Ausgaben sind von dem Modell generierte vorhergesagte Antworten. Der Algorithmus wendet die Rückwärtspropagation an, um eine Verlustfunktion (z. B. Kreuzentropie) über den Trainingsdatensatz zu minimieren. Gestaltungsentscheidungen umfassen den Validierungs-Splitt-Verhältnis (z. B. 80-20) und die Auswahl zwischen vollständigem und effizientem Fine-Tuning. Kompromisse bestehen darin, dass ein vollständiges Fine-Tuning höhere Rechenkosten und ein Überanpassungsrisiko mit sich bringt, gegenüber potenziell reduzierten Leistungssteigerungen und katastrophalem Vergessen bei parameter-effizienten Ansätzen.

#### 3. Vergleich der Wissensinjektion

RAG integriert während der Inferenz externes Wissen, indem es relevante Dokumente aus einer Vektordatenbank (z. B. mithilfe von `cosine_similarity` zur Passageübereinstimmung) abruft und diese Kontextinformationen vor der Generierung zur Eingabeabfrage hinzufügt. Im Gegensatz dazu aktualisiert das unsupervised Fine-Tuning die Modellgewichte über Gradientenabstieg anhand von Trainingsbeispielen (Eingabe: Frage-Antwort-Paare; Ausgabe: angepasste Parameter), wodurch das Modell Fakten parametrisch internalisieren muss. Ovadia et al. (2023) zeigen, dass Fine-Tuning Schwierigkeiten hat, neue fakтиsche Informationen zu lernen, da der parametrische Speicher des Modells nicht effizient neue Fakten aufnimmt, und dass das Exponieren der Modelle während des Trainings an zahlreichen Varianten desselben Fakts dieses Problem mindert. RAG umgeht diese Einschränkung, indem es Wissen von Gewichten entkoppelt und dadurch direkte Wissensaktualisierungen ohne Neutraining ermöglicht. Der Kompromiss bei RAG besteht in der Abhängigkeit von einem hochwertigen Retrieval-System (was Latenz und potenzielle Retrievalfehler einführt), während der Kompromiss beim Fine-Tuning in dem Bedarf besteht, umfangreiche Trainingsdatenvarianz zu benötigen, um selbst geringfügige Faktenbeibehaltung zu erreichen, was es für die Integration dynamischen Wissens ineffizient macht.

#### 4. Kosten, Latenz und Wartung

RAG verursacht eine einmalige Indexierungskosten für die Wissensbasis (z. B. das Einbetten von Dokumenten in eine Vektordatenbank) und eine pro-Abfrage-Kosten, die von der Retrieval-Latenz dominiert wird (z. B. `O(k log n)` für `k`-nächste Nachbarn in einem `n`-dimensionalen Index). Fine-Tuning erfordert einen hohen anfänglichen Trainingsaufwand (Neutraining des Modells auf neuen Daten), hat aber eine geringe pro-Abfrage-Kosten (nur Inferenz). Das Aktualisieren von Wissen in RAG erfolgt durch das Hinzufügen oder Löschen von Dokumenten im Index (z. B. über [[vector-databases|Vektordatenbanken]], wodurch kein Modell-Neutraining erforderlich ist. Im Gegensatz dazu erfordert Fine-Tuning ein vollständiges Neutraining bei jedem Wissensupdate, was zu erheblichen Wartungsaufwand führt. Balaguer et al. (2024) haben dies in einem Fallbeispiel aus dem landwirtschaftlichen Bereich gezeigt: RAG ermöglichte einen 5 p.p. Genauigkeitsgewinn, der sich mit dem 6 p.p. Verbesserung durch Fine-Tuning kumuliert, aber das fine-tuned Modell erforderte Neutraining, um neues geografisches Wissen zu integrieren, während RAG kontinuierliche Updates ohne Neutraining ermöglichte.

#### 5. Beide kombinieren (RAFT)

RAFT (Retrieval Augmented FineTuning), eingeführt von Zhang et al. (2024), trainiert ein Modell, um Antworten direkt aus abgerufenen Dokumenten zu generieren, während es relevante Abschnitte explizit zitiert. Der Eingabedatenbestand besteht aus einer Frage, einem Satz abgerufener Dokumente (einschließlich Ablenkungen) und einer Zielantwort mit wörtlichem Zitat. Das Modelloutput integriert das Zitat in eine chain-of-thought-Antwort und unterdrückt Ablenkungen über eine Kreuzentropie-Verlustfunktion, die die Extraktion von Abschnitten gegenüber der Generierung priorisiert. Die Struktur der Trainingsdaten besteht aus Dreier-Tupeln (Frage, abgerufene_Dokumente, zitiert_er_Passage), wobei Ablenkungen bewusst eingeschlossen werden, um dem Modell beizubringen, irrelevanten Inhalt zu filtern. Die Designentscheidungen priorisieren Transparenz und faktenbasierte Grundierung: das wörtliche Zitieren reduziert Halluzinationen, indem es Antworten an den Quelltext anbindet, erfordert aber eine hochwertige Retrieval-Operation, um sicherzustellen, dass der relevante Abschnitt vorhanden ist. Dies führt zu Kompromissen: erhöhte Trainingskomplexität aufgrund der Ablenkungsbehandlung und der Anforderungen an präzise Passage-Extraktion, im Gegensatz zu einer verbesserten Antwortzuverlässigkeit. RAFT erweitert [[retrieval-augmented-generation|retrieval-augmented generation]] durch das Einbetten des Retrieval-Kontexts in die Gewichte des Modells, und [[llm-adaptation|fine-tuning]] durch das ermöglichen von domain-spezifischen faktenbasierten Ausrichtungen ohne Neutraining des gesamten Modells.

#### Ursprung und Varianten

RAG, formalisiert von Lewis et al. (2020), integriert parametrisches Gedächtnis (ein vortrainiertes sequenzielles Modell) und nicht-parametrisches Gedächtnis (einen dichten Vektorindex externer Dokumente) zur Sprachgenerierung. Eingaben bestehen aus einer Benutzeranfrage und abgerufenen Dokumenten (aus dem nicht-parametrischen Index über einen neuronalen Retriever), wobei die Retrieval-Scores als `score = 1 / (k + rank)` berechnet werden. Das System erzeugt eine Antwort, die auf sowohl der Anfrage als auch den abgerufenen Passagen basiert. Das nicht-parametrische Gedächtnis verwendet einen Approximate Nearest Neighbor-Index (z. B. FAISS) für effiziente Dokumentabfragen, während der parametrische Teil die Generierung übernimmt. Die Gestaltungswahl priorisiert dynamische Wissensaktualisierungen ohne Neutraining, wodurch externe Wissensquellen unabhängig weiterentwickelt werden können. Kompromisse umfassen die Abhängigkeit von der Retrieval-Qualität (fehlende Dokumente verringern die Genauigkeit der Ausgabe) und die erhöhte Latenz durch den Retrieval-Schritt, im Gegensatz zur statischen Wissensintegration durch Fine-Tuning, vermeidet jedoch das Bedürfnis nach Gewichtsaktualisierungen. Diese Architektur unterstützt faktenbasierte Verankerung und Quellenzuordnung, obwohl Retrieval-Fehler weiterhin eine zentrale Einschränkung darstellen [[rag-retrieval|Retrieval]] und sich grundlegend von der Gewichtsmodifikationsmethode von [[llm-adaptation|Fine-Tuning]] unterscheidet.

### Wann einsetzen

- Für wissensintensive Aufgaben, die neue oder häufig aktualisierte faktenbasierte Informationen erfordern, da RAG solche Aufgaben konsistent besser bewältigt als das Feinabstimmen (Ovadia et al., 2023).
- Für Anwendungen, die eine explizite Quellenangabe für generierte Antworten erfordern, da RAG relevante Dokumente abruft und zitiert (Lewis et al., 2020).
- Für Szenarien, die große, externe Wissensdatenbanken beinhalten, die unabhängig von Modellupdates verändern, da RAG eine dynamische Wissensintegration ermöglicht (Balaguer et al., 2024).

### Stärken und Grenzen

**Vorteile**
- RAG übertrifft konsistent die nicht überwachte Feinabstimmung bei wissensintensiven Aufgaben sowohl für bestehendes als auch für neues Wissen (Ovadia et al., 2023).
- RAG erzielt state-of-the-art Ergebnisse bei Aufgaben des offenen Domain-Fragebeantwortens, wobei spezifischere, vielfältigere und faktuellere Sprache generiert wird (Lewis et al., 2020).
- RAG erhöht die Genauigkeit um 5 Prozentpunkte in domänenspezifischen Anwendungen (Balaguer et al., 2024).

**Einschränkungen**
- RAG benötigt zusätzliche Infrastruktur für [[rag-retrieval|Abfrage]] und Indizierung (Lewis et al., 2020).
- Standard-RAG kann darin scheitern, Stördokumente zu ignorieren, was zu ungenauen Ergebnissen führen kann (Zhang et al., 2024).

### Vergleich

| Ansatz | Unterschiede | Geeignet für |
|----------|----------------|------------|
| RAG | Integriert externe Kenntnisse während der Inferenz über Dokumentretrieval, ohne die Modellgewichte zu ändern. | Wissensintensive Aufgaben, die aktuelle, externe oder häufig aktualisierte faktenbasierte Informationen erfordern. |
| Fine-Tuning | Ändert die Modellgewichte durch Training auf datenspezifischen Aufgaben, wodurch Wissen direkt in die Modellparameter eingebettet wird. | Anpassen des Modellverhaltens für spezifische Aufgaben, domänenspezifische Stile oder statische Wissensdatenbanken. |
RAG ist hervorragend darin, neue faktenbasierte Informationen ohne Neutraining zu integrieren (Ovadia et al., 2023), während Fine-Tuning effizienter für statische Domänenanpassung ist [[llm-adaptation|LLM-Anpassung]].

### In der Praxis

Die Bewertung erfordert eine separate Beurteilung der Retrieval-Effektivität (z. B. `Recall@k`) und der Generationsgenauigkeit, wie im [[rag-evaluation|Bewertung]] detailliert beschrieben. Das Fine-Tuning schlägt oft fehl, neue fakтиsche Kenntnisse ohne mehrere Varianten desselben Fakts zu integrieren (Ovadia et al., 2023). Ein entscheidender RAG-Parameter ist die Kontextverwaltung: den vollständigen Antwortkontext mit einem einzigen abgerufenen Kontext zu verwenden oder dynamischen Kontext pro Token, wobei letzterer die Generationsqualität verbessert (Lewis et al., 2020).

### Merksatz

RAG erweitert dynamisch den Schlussfolgerungskontext mit externem Wissen, um aktualisierbare fakтиsche Informationen (mit potenziellen Retrieval-Fehlern) zu unterstützen, während Fine-Tuning das Wissen dauerhaft in die Modellgewichte einbettet, um das Verhalten für spezifische Aufgaben anzupassen (wodurch Neuerlernen für neue Fakten erforderlich ist).
